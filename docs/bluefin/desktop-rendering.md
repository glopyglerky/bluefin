# Embedded desktop rendering

The native default uses eframe/egui_glow 0.33.3 and libmpv's documented OpenGL render API. Video renders into a viewport-sized RGBA8 texture/FBO and blits to egui's intermediate framebuffer, with clipping and physical-pixel sizing. The two axes are bounded to 4096×2160; larger viewports upscale that bounded render surface. libmpv preserves display aspect through letterboxing. No external player/window or browser is used.

`--wgpu` selects software video. A missing GL owner or failed initial GL render-context creation also selects software video before media load. Software output follows observed video display dimensions, preserving aspect with a 4096×2160 allocation ceiling and a one-frame latest mailbox. It consumes CPU and upload bandwidth and is a compatibility path. Audio-only playback produces no software frames. Stop/replacement/account retirement retains existing decoder-plus-transport receipts. Runtime GL loss or incomplete framebuffer stops playback with a decoder error; it does not silently replay the stream.

The player shows observed source dimensions, codec, audio sample rate/channel count, `hwdec-current`, source transfer and render path. An unavailable property is not hardware evidence. `auto-safe` requests hardware decoding where supported; the adapter does not supply native X11/Wayland display handles for direct surface interop, so platform hardware paths can remain unavailable or copy surfaces internally. RGBA8 is SDR: libmpv is configured for BT.709 primaries, sRGB transfer and BT.2390 tone mapping on the GL path. Source HDR/HLG/PQ metadata does not imply HDR display output. Dolby licensing, perceptual quality, physical GPU/decoder/speaker and native HDR output require separate platform evidence.

## Ownership and unsafe invariants

The decoder control thread creates/initializes the core, applies configuration, handles commands/events/properties, and destroys it. The render owner calls only render APIs; no UI paint callback waits for a client API or network operation. Startup remains off the UI thread. The render context is created before loadfile. Render calls disable target-time blocking; the existing UI repaint cadence drives presentation, and video-timing-offset is zero. This is not measured audiovisual synchronization on a physical device.

GL tickets contain the initialized core address and an Arc retaining its loaded ABI library, plus an atomic lease state. This is not a transferable GL render context or a Send/Sync implementation for GL objects. The control thread keeps its core alive while the ticket is initializing/ready and waits for retirement before destroying it. Pending startup has a three-second fallback deadline, claimed with compare-exchange so it cannot race GL creation. Initialization claims the lease before dereferencing the address; software fallback is allowed only after initialization has failed or pending ownership was atomically canceled. A current GL operation cannot be preempted by the startup timer.

The actual GL render pointer, FBO and texture live in a thread-local owner. Only egui_glow callbacks and eframe on_exit invoke its unsafe methods, with the original primary GL context current. Callbacks do not capture raw handles. The owner verifies the painter's Arc context identity and never migrates the render context. This implementation uses one primary app viewport; adding detached viewports requires a fresh context-ownership review. Platform symbol dispatch is loaded through GLX, WGL or the public macOS OpenGL framework, retained for the owner's lifetime. No private APIs or arbitrary unsafe Send/Sync implementations are used.

Retirement frees libmpv rendering state and owned GL objects on that owner before publishing phase 3. The decoder then joins software rendering if present, stops and destroys the core, and only afterward publishes stopped. Existing Player cleanup additionally requires the checked transport stop/drain receipt. No render/update/wakeup callback is registered with libmpv, so there is no callback userdata to retire. Eframe on_exit explicitly retires the GL owner; a panic/abrupt process death is not acknowledged cleanup. The thread-local has no GL-calling destructor that could run after context destruction.

libmpv render_gl.h requires default GL state around its calls. The callback clears egui's program/VAO/array binding for initialization, disables scissor/blending for rendering and restores the painter framebuffer afterward. Pinned egui_glow reestablishes its own paint state after each callback. GPU blits restore clipping and honor the callback's physical viewport. Fresh/resized surfaces are cleared black, including before video is available. GL creation/allocation failures release partial objects. An incomplete FBO, render error or observed GL_CONTEXT_LOST retires the renderer and stops its core. Lost current-context ownership outside the eframe contract is not something raw-handle checks can repair.

FFI layouts and numeric parameter tags match the public libmpv 0.35 headers. C strings and parameter storage remain valid during each synchronous call. Property strings are copied and released once through the loaded library's `mpv_free`. Software pixel storage uses aligned u32 elements and checked bounded dimensions; no foreign buffer is retained by Rust. The loaded library remains alive until both core and renderer retirement. libmpv, FFmpeg, EGL/GL and the OS remain upstream native dependencies, with their own memory-safety and licensing boundaries.

## Evidence boundaries

The project test runner can create an existing surfaceless EGL pbuffer and run the same renderer without opening a GUI or controlling a device. It verifies actual nonblack framebuffer output above 540p, resize, square-viewport letterboxing, no CPU-frame mailbox on GL and core retirement after context destruction. A Mesa software renderer validates API/framebuffer behavior, not physical GPU acceleration. Software tests cover 1080p source retention, aspect/memory bounds and absent-owner fallback. Existing headless tests cover audio-only, seek, live/HLS, account retirement, queue progression and stop receipts. No headless result establishes desktop installation, display quality, hardware decode, native HDR or audible output.
